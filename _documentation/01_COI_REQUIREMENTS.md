# COI Input and Form Rules

## Upload formats

The upload validator and extractor registry accept `.pdf`, `.docx`, `.doc`, `.xlsx`, `.ods`, `.png`, `.jpg`, `.jpeg`, `.jpe`, and `.tiff`. The declared extension must match the detected file signature. ZIP-based Office files are recognized by ZIP signature; legacy `.doc` uses the OLE2 signature. The configurable upload limit defaults to 20 MiB.

Filenames are limited to 250 characters and reject `; : > < / \\ | ' * % $`. Uploaded bytes are read by the API into memory. Extraction uses byte streams except legacy `.doc`, which LibreOffice converts in a temporary directory before extraction. The Docker backend mounts `/tmp` as a size-limited `tmpfs`; deployments using legacy `.doc` must keep its temporary directory ephemeral. The backend container also has a read-only root filesystem.

## Polish field recognition and validation

`DeterministicFormStructurer` infers field types from labels and values and validates PESEL, NIP, REGON, postal codes, email addresses, dates, and phone numbers. The mapper emits COI validation labels `PESEL`, `NIP`, `REGON`, `ZIP_CODE`, `EMAIL`, and `DATE` where applicable. It also supports `PHONE`. PESEL checks include length, checksum, and encoded birth date; NIP and REGON use their respective checksum rules; postal codes use `NN-NNN`; dates are parsed against supported date formats; email and phone use local regular expressions.

The COI mapper assigns dictionary names based on labels: `Kraje`, `Województwo`, `Powiat`, `Gmina`, `Miejscowość`, and `Numery kierunkowe`. These are names in generated form definitions; this repository contains no bundled dictionary dataset or dictionary lookup endpoint.

For applicant fields, the mapper can set default-value references `PESEL.name`, `PESEL.surname`, and `PESEL.pesel`. These are output references for downstream form behavior. The application does not call an external PESEL registry or retrieve registry data.

## Consents and conditional visibility

The mapper scans extracted paragraph and raw text for `wyrażam zgodę`, `klauzula informacyjna`, `przetwarzanie danych`, and `RODO` cues and can add a consent section. This is heuristic text recognition, not a legal classification or a complete RODO compliance check.

Conditional fields use `states` with `type: "SHOW"` and a JSONata query. Multi-application forms can receive a required `Rodzaj wniosku` selector; generated application tabs carry `SHOW` states based on the selected option. The frontend preview evaluates the mapper's limited selector-query shape locally. Queries outside that shape default to visible; this is not a general JSONata runtime.

## FormDefinition output

Digitization returns the COI `FormDefinition` object as `form_definition`. The frontend can download it as UTF-8 JSON using `konfiguracja_form_<slug>.json`, where `<slug>` is derived from the form title. The output is generated by `DeterministicFormDefinitionMapper` and contains `title`, `tabs`, and `flow`; it does not depend on an in-repository official schema or dictionary bundle.
